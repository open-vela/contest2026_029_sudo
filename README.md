## 一、作品简介

**《资料库》是一款完全离线运行的手表端知识检索应用**。它把历史、诗词、英语、健康、生活、学习六大类共 **5400 条**结构化资料装进手表，用户在表盘上用**极短的关键词**（一两个汉字即可）就能秒级定位到条目，并在详情页查看完整内容。

设计初衷来自一个真实痛点：**手表屏幕小、输入难、网络不可靠**——所以它不依赖任何云端服务，所有索引与内容都常驻腕上；交互也围绕"少打字"设计：能用一次点击完成的，绝不要求用户敲第二个字。

作品基于 openvela 快应用框架（`.ux` 单文件组件，类 Vue 语法）开发，可运行于 openvela 模拟器与真实手表设备。

## 二、核心功能

### 1. 离线搜索引擎（自研，零第三方依赖）

纯 JS 实现了完整检索链路：

- **哈希分桶索引**：资料按 token 哈希散列到 2048 个桶，检索时先定位桶再取候选，避免全量扫描；
- **逐字分词 + 前缀匹配**：中文按单字入桶（「健康」拆成「健」「康」两字均可命中），英文按 3~N 位前缀入桶（输入 `proj` 能命中 `project`）；
- **跨集聚合搜索**：一次检索遍历全部资料集，结果按「各集轮流取样」交错排序，避免某一集占满首页；
- **两级缓存**：块索引与 Map 数据缓存于设备 storage，二次检索显著快于首次。

### 2. 六大资料集 + 标签筛选

首页以 6 个入口组织全部资料，**点击任意资料卡进入独立的资料详情页**：

- 展示**资料图标、资料简介**，以及从数据中提取的**全部标签**（原分类词）；
- **点标签即筛选**：标签变蓝表示"只看带这个标签的资料"，例如在「健康」里只看「急救」；
- 支持进入资料后直接输入关键词搜索，搜索范围自动限定在该资料（含选中标签）内。

| 资料 | 条目数 | 标签（原分类词）示例 |
| --- | --- | --- |
| 历史 | 850 | 亚洲 / 欧洲 / 非洲 / 南美洲 / 北美洲 / 其他 |
| 诗词 | 550 | 诗 / 词 / 先秦 / 魏晋 / 唐朝 / 五代 / 宋朝 / 元朝 / 清朝 |
| 英语 | 750 | 四级 / 六级 |
| 健康 | 1000 | 健康 / 心理情绪 / 急救 / 护肤美妆 / 运动 |
| 生活 | 1200 | 亲子育儿 / 出行旅游 / 厨房烹饪 / 宠物照料 / 房屋维修 / 民俗常识 / 理财省钱 / 职场办公 / 节气节日 / 衣物打理 … |
| 学习 | 800 | 学习效率 / 手机数码 / 百科 |

### 3. 词条详情

条目名、所属资料与年代、关键词标签、正文分字段呈现——**字段名与数量由各资料的 `meta.json` 声明**，非页面硬编码，新增资料集无需改页面。

### 4. 收藏与快捷入口

收藏夹支持查看与移除；首页第二屏提供「设置 / 收藏」快捷卡片。

### 5. 资料集可扩充（架构预留）

资料集以「独立文件夹 + meta 自描述」组织：每个集自带字段声明、分片数据与哈希索引，理论上可通过手机蓝牙向手表 `files` 区推送新集并动态注册；内置资料亦支持应用覆盖更新。

## 三、技术亮点

### 1. 模块化资料集（可插拔）

每个资料集是**自包含目录**：`meta.json`（字段角色声明）+ `meta.txt`（引擎物化视图）+ `map_*.txt` / `detail_*.txt`（分片）+ `block_0.txt`（哈希索引）+ `icon.png`。集数 = 首页入口数，增删资料不动一行业务代码。

### 2. 数据侧与引擎侧分词严格对齐

入桶分词必须与查询分词**完全一致**，否则会出现"数据里明明有、就是搜不到"的隐蔽缺陷。工程用同一份 `tokenize` 规则生成索引，并与引擎 `_parseQuery` 逐条对齐（含"纯字母词入 3..len 全部前缀、其余逐字符入桶"的细则）。

### 3. 面向小屏的性能工程

手表的内存与 I/O 远弱于手机，工程为此做了多项针对性优化：

- **结果区独立滚动容器**：结果列表在固定高度内自滚，页面总高恒定，避免超长滚动内容的滚动与重排开销；
- **渐进显示**：搜索结果默认只渲染 5 条，点「显示更多」再追加，把单次渲染节点数压到最低；
- **翻页成本恒定**：跨集聚合时每集只调用一次引擎（取前 `pageSize × page` 条后本地切片），避免"翻到第 N 页就检索 N 次"的乘数放大；
- **禁用动态 style 绑定**：全部改为 `computed` 预拼类名 + 模板纯变量插值——动态内联样式在小屏固件上既拖慢渲染，还可能触发 DOM 属性异常；
- **形态差异由 `@media` 固化**：胶囊屏／方形屏的尺寸差异全部在样式层声明，运行时不计算布局。

### 4. 稳健性处理

- 文件读取回调在部分打包模式下存在丢失风险，因此**搜索链路设置双层超时兜底**（单集 8s / 页面 10s），保证界面不会"假死"；
- 引擎内存淘汰（LRU）循环带**上限非零断言**，避免上限被配置为 0 时 `length >= 0` 恒真导致的死循环；
- 缓存键携带数据版本号，数据更新后旧缓存自动失效；并提供「关于」连点四下清空全部缓存的手动入口。

### 10.2 检索引擎 `SearchEngine.js`（1683 行）

- **哈希分桶倒排索引**：`hashCode()` 为 DJBXOR 变体（初始 5381，`hash = hash*33 ^ charCode`），桶数 **2048**；中文逐字入桶、英文按 1..N 前缀入桶，**与查询侧共用同一套实现**，保证求交非空。
- **两级 LRU 缓存**：Map（卡片）与 Block（倒排块）各自按访问顺序淘汰，上限 **Block 2 / Map 2**（v1.16.94 为防真机爆内存从 4 收紧到 2）；淘汰的只是内存副本，storage 持久缓存仍在，重载便宜。LRU 实现带「上限为 0 会死循环」的防护。
- **渐进式分片加载**：读完倒排桶后按命中数排序加载前若干 Map 分片即可出首屏结果，翻页逐片加载，跨分片命中不漏；被淘汰分片的命中行在首次提取时固化进搜索态 rows，因此翻页正确性与缓存淘汰解耦。
- **并发安全**：多块求交时临时抬升 LRU 上限，并用**所有权标记**还原（仅当当前值仍属本次抬升才还原），防止并发搜索互相覆盖。
- **耗时可观测**：每次 `search()` 把分阶段耗时（`stepTimings`）写入运行时日志，性能数据可复现。

### 10.3 跨集调度 `DatasetManager.js`（437 行）

- **一集一行的注册表**：`DATASETS` 自描述清单（id / 目录 / 名称 / 图标 / 描述 / 筛选标签），新增资料集只需追加一行，引擎与 UI 零改动。
- **按集隔离缓存**：`ensureEngine(ds)` 统一创建引擎并注入 `basePath`（内置集 `/common/datasets/<集>/`，蓝牙动态集 `internal://files/datasets/<集>/`），缓存 key 带 `_ds<id>` 后缀避免各集同名覆盖。
- **顺序逐集累加、凑够即停**：按查询词散列出的起点轮转集顺序（同一查询结果可复现），累计卡片数达到 `pageSize×page` 即停止本轮；点「显示更多」才继续搜索后续集——既避免一次拉起过多分片造成卡顿，也避免某一集长期霸占首批结果。
- **后台预热**：首启后 `warmupAllCaches/warmupOne` 填充各集引擎实例与持久缓存，每步 `yield` 一帧不与 UI 抢主线程，使首次总搜索不再冷读块文件。

### 10.4 详情读取 `DatasetDetail.js`（126 行）

- **一套代码三种版式**：全局 ID → 解码 `datasetId`/`localId` → 定位集与分片 → 按 `meta.fields.detail` 声明的列序拆字段。因此历史集（原因/背景、影响/做法）、诗词集（出处、正文、译文）、英语集（释义、例句、搭配）三种完全不同的详情版式**共用同一套实现**。
- **健壮性**：字段名中文化经 `FIELD_NAME_MAP` 映射；meta 读取失败时按历史集列序兜底，保证不出现空白详情；详情内存缓存只留一页（LRU=1），退出详情页主动清空。

### 10.5 蓝牙资料接收 `BtTransfer.js`（226 行）

- **分片协议**：`ds-begin`（声明总文件数）→ `ds-chunk`（文件序号 + 分片序号）→ `ds-end`（落盘校验 + 注册）→ `ds-abort`（清理）。
- **流式落盘**：单文件分片收齐即写盘并从内存释放（避免整集驻留内存导致 OOM）；ds-end 用 **okCount/failCount 计数**校验，并保留失败文件记录用于精确报错与补落——此处曾因「用存活键计数」在流式落盘下必然误报「文件数不符」，已修复。
- **免重装扩展**：落盘到应用沙箱并注册为动态集后，与内置集享有同等检索体验，**整集资料无需重装应用即可扩展**。

### 10.6 助手链路 `AssistantEngine.js`（488 行）

- **双链路自动探测**：`getReadyState` 判断手机互联通道是否可用 → 可用走真链路，否则降级本地模拟（`MODE.SIM`）并在界面如实标注。
- **异常防护**：`ai_chat` 带自增序号（qid）与超时，迟到回包按序号拦截，防止旧答案污染新问题；与 BtTransfer 共用 `conn.onmessage` 时采用「保留原 handler + 非本模块消息转发」的包装链。
- **解析双兼容**：同时接受 `{data:'<json>'}` 包装与裸字符串/对象投递。

### 10.7 三形态主界面 `index.ux`（1766 行）

- **双屏吸附结构**：第一屏（搜索框 + 六大分类图标 + 语音/AI 入口）、第二屏（设置/收藏卡片），两屏高度由 `screen1H` 统一驱动。
- **胶囊屏可用高度动态换算**：`可用设计高 = 屏高 × designWidth(300) ÷ 屏宽`。公式自检：方屏 `480×300÷336 = 429`，与既有硬编码一致；胶囊屏 `520×300÷212 = 736`，修正了原硬编码 766 导致的底部按钮被裁。
- **图标横向吸附**：`snapParams` 按各形态的图标宽/间距/左内边距分别整定，保证任意形态下图标都能吸附到屏幕中心。

### 10.8 内置输入法 `InputMethod.ux`（871 行）

- 三态键盘（中文拼音/英文/数字符号）× 三形态分支（方屏水平键盘 / 圆屏缩放键盘 / 胶囊弧形键盘）；候选字由内置拼音字典实时检索，**单字候选、一行 6 列**展示。
- **一处根因定位记录**：候选「更多」面板的单元格宽度必须显式声明（`.cand-cell` 16%），否则内部 `input` 会按字号取文字固有宽（约 150px），一行 6 个塞不进 304px 面板而**只显示 2 个**。

### 10.9 资料生产工具链 `tools/`

- **建索引侧与查询侧共享同一套分词与哈希**（`tools/lib/dataset_core.js` 与 `SearchEngine._parseQuery` 逐字对齐），避免「入桶用一套规则、查询用另一套」导致交集为空——这是资料工程里最容易踩、也最难查的坑。
- **七项质量校验**（`verify_dataset.js`）：分片完整性、ID 连续性、列数与 meta 声明一致、桶号范围、字段非空、格式字符安全、总量核对。
