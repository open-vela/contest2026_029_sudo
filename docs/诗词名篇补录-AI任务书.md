## 三、现状与根因

### 3.1 数据源格式

`poems_10000条_cleaned (1).txt`：10000 行，每行 **8 个字段**，用 `|` 分隔：

```
ID|标题|作者|朝代|出处|原文|译文|（第8字段）
```

真实首行（已截断）：

```
1|关雎|佚名|先秦|诗经|关关雎鸠，在河之洲。窈窕淑女，君子好逑。……|雎鸠鸟关关地叫着，双双飞落在河中的小洲上。……|……
```

- **第 6 字段 = 原文**（古诗文原句）
- **第 7 字段 = 白话译文**（现代汉语翻译）
- 第 8 字段内容未使用

> 注意：数据源里**没有**静夜思、登鹳雀楼、早发白帝城、江雪、咏鹅等名篇（是《全唐诗》式冷门库），所以**必须新增数据行**，不能只改选录规则。

### 3.2 生成脚本的缺陷（名篇全缺的根因）

`tools/build_poems_dataset.js` 中：

```js
// 精简：按正文长度降序取前 800（主人要求「长的/信息完整的优先」）
const POEMS_TARGET = 550;
if (records.length > POEMS_TARGET) {
  records.sort((a, b) => ((b.content || '').length) - ((a.content || '').length));
  records.length = POEMS_TARGET;
}
```

按正文长度降序取 550 → 选中的全是《秋日夔府咏怀奉寄郑监李宾客一百韵》这类 2000 字超长冷门诗；
《静夜思》(20 字)、《春晓》(20 字) 排在 10000 名开外，**永远选不上**。

当前 550 首构成：杜甫 182 首、佚名 75 首（诗经）、高适 36 首、李白 22 首……全部是中长篇。

### 3.3 输出格式（改动时必须保持，否则 App 读不出来）

脚本向 `src/common/datasets/poems/` 写这些文件：

| 文件 | 格式 | 说明 |
|---|---|---|
| `map_N.txt` | `localId\|0\|朝代序号\|标题·作者` | 每 200 条一片（`MAP_CHUNK`） |
| `detail_N.txt` | `localId\|标题,作者,朝代,出处\|出处\|原文` | 每 100 条一片（`DETAIL_CHUNK`）；原文里的真实换行必须写成字面 `\n` 两个字符 |
| `block_0.txt` | `桶号\|id1,id2,…` | 只对「标题/作者/朝代/出处」分词入桶（**正文不入索引**） |
| `meta.txt` / `meta.json` | JSON | 脚本自动生成，含总条数、朝代表、分片表 |

`localId` 由脚本按数组顺序重编号（0..N-1）。**改选录规则会导致全部 id 位移**，App 里已收藏的条目会指向错误的诗 —— 赛前数据可整体重置，可接受，但要知道这件事。

## 四、要做的改动

### 改动 1：新增名篇数据（主要工作量）

**方式**：新建文件 `E:\vela Project\资料\poems_famous.txt`，格式与源文件**完全一致**（8 字段、`|` 分隔、UTF-8 无 BOM），一行一首。
最后可留空的第 8 字段补一个空串即可（即行尾两个 `|`）。

**示例行**（照这个格式写）：

```
90001|静夜思|李白|唐朝|诗|床前明月光，疑是地上霜。举头望明月，低头思故乡。|明亮的月光洒在床前，好像地上泛起了一层白霜。我抬起头望着天上的明月，又低下头思念起故乡。|
90002|春晓|孟浩然|唐朝|诗|春眠不觉晓，处处闻啼鸟。夜来风雨声，花落知多少。|春天睡得香甜，不知不觉天就亮了，醒来听到处处都是鸟叫声。想起夜里那阵风雨声，不知道花儿被打落了多少。|
```

**ID 规则**：从 `90001` 起递增，不要与现有 1..10000 冲突。

**朝代取值**：只能用 `先秦` `魏晋` `唐朝` `五代` `宋朝` `元朝` `清朝` 这 7 个（脚本按数据里出现的朝代建表，App 的筛选标签也只列了这些）。
明朝、汉、南北朝、隋朝的诗（如《石灰吟》《墨梅》《长歌行》）**统一就近归入**：
- 明朝 → 归入 `清朝`（同属后期，避免新增朝代）
- 汉乐府、南北朝 → 归入 `魏晋`
- 隋 → 归入 `唐朝`

**出处取值**：`诗` `词` `曲` `诗经` `楚辞`，与现有数据保持一致（`诗` 最多；词牌名作品填 `词`；散曲小令填 `曲`；《诗经》篇目填 `诗经`；《楚辞》篇目填 `楚辞`）。

**内容准确性要求（最重要）**：
- 原文必须是**逐字准确**的通行版本，不得有错别字、漏句、自行改写；
- 不得凭印象编造诗句。**不确定的诗句必须联网核对**（古诗文网、汉典、维基文库等），或改用你能 100% 确定的版本；
- 标点统一用全角 `，。！？、；：`，句末加句号；
- 长诗（如《琵琶行》《长恨歌》）可只收录**教材必背段落**，并在标题后加 `（节选）`，原文注明"节选"；
- 译文写完整的现代汉语翻译，一句原文对应一句译文。

### 改动 2：修改生成脚本的选录规则

在 `tools/build_poems_dataset.js` 里：

1. **读入两个数据源**：先读 `poems_famous.txt`（必收），再读 `poems_10000条_cleaned (1).txt`（备选池）；
2. **必收清单无条件保留**，不参与长度排序淘汰；
3. 备选池按正文长度降序补足到目标条数；
4. 目标条数提高到 **≥800**（必收 200+ 首 + 备选补足）；`POEMS_TARGET` 相应调整；
5. 其余逻辑（格式、分片、分词入桶、meta 生成）**保持不动**。

参考改法（示意，按实际代码结构落地）：

```js
const famous = parseSource(path.join(__dirname, '..', '..', '资料', 'poems_famous.txt'));
const pool   = parseSource(path.join(__dirname, '..', '..', '资料', 'poems_10000条_cleaned (1).txt'));
const POEMS_TARGET = 800;
// 必收优先，池子按内容长度降序补足；同名同作者去重（famous 优先）
const seen = new Set();
const records = [];
for (const r of [...famous, ...pool]) {
  const key = r.title + '|' + r.author;
  if (seen.has(key)) continue;
  seen.add(key);
  records.push(r);
}
records.sort((a, b) => ((b.content || '').length) - ((a.content || '').length));
// 必收不参与淘汰：先切出必收，再补足池子
```

> 实现要点：不要简单地"排序后取前 N"，否则必收清单又被挤掉。必须先固定必收集合。

### 改动 3（可选，收益高）：详情页同时显示原文与译文

源数据里本来就有译文（第 7 字段），目前被丢弃了。若时间允许，让详情页显示「正文 + 译文」两段，观感更完整：

1. `poems_famous.txt` 与主源都解析出 `translation`；
2. 生成 `detail_N.txt` 时多拼一段：`localId|标题,作者,朝代,出处|出处|原文|译文`；
3. `src/common/datasets/poems/meta.json` 的 `fields.detail` 改为 `["source", "content", "translation"]`；
4. `src/SearchEngine/DatasetDetail.js` 的 `FIELD_NAME_MAP` 增加一条映射：`translation: '译文'`（否则字段名会显示成英文 `translation`）。

> 只做改动 1、2 也能满足本任务验收；改动 3 是加分项，做与不做都要在交付里说明。

## 附录 B：常见坑（踩过，别再踩）

1. **不要手工编辑 `src/common/datasets/poems/` 下的任何文件** —— 它们是生成产物，下次跑脚本就被覆盖；
2. **正文里的真实换行必须转义成字面 `\n`** —— 裸换行会把一条记录劈成两行，导致后续所有记录 id 错位；
3. **正文里不能出现 `|`** —— 会把列切错（脚本已有 `\|→｜` 兜底，但新增数据请直接避免）；
4. **不要只改选录条数不改排序规则** —— 那样仍然只选出长诗；
5. **改完必须同步镜像目录**，否则比赛仓和开发仓不一致（评审看的是比赛仓）；
6. **构建后必须递增版本号**（`src/manifest.json`），并记录时间点。
