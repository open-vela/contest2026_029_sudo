# 资料拆分指南（人类版）

> 本文档解释《资料库》手环应用的资料集格式，以及如何用通用拆分工具
> 准备、修改、重建任何一个资料集。读完本文你不需要懂引擎代码就能独立拆分资料。
>
> 工具入口：`tools/split_dataset.js`（拆分）· `tools/verify_dataset.js`（校验）
> 规则唯一实现：`tools/lib/dataset_core.js` —— **改拆分规则只改这里**，不要另写脚本。

---

## 1. 一条资料的一生

```
你准备的源文件（纯文本，一行一条资料）
        │  tools/split_dataset.js + tools/specs/<集名>.json
        ▼
┌──────────────────────────────────────────────┐
│  解析 → 采样 → 重编号 → 拆分 → 写盘           │
│  （全部规则集中在 tools/lib/dataset_core.js）  │
└──────────────────────────────────────────────┘
        ▼
map_N.txt（目录条目） detail_N.txt（详情内容） block_0.txt（搜索倒排桶）
meta.txt（引擎视图）  meta.json（人类视图）   icon.png（图标）
        ▼
打包进 rpk → 手环引擎按需加载
```

## 2. 资料集文件格式（逐文件说明）

所有 `.txt` 的共同约定：**行以 `\n` 分隔，文件末尾不带换行，禁止 `\r`，UTF-8 无 BOM。**

### 2.1 `map_N.txt` —— 目录条目（每 `mapChunkSize` 条一片）

```
localId|year|regionIdx|标题
0|0|2|切 HAL_PROT_INFO 相关静态变量
1|-44|0|凯撒遇刺
```

| 列 | 含义 | 备注 |
|---|---|---|
| localId | 条目编号 | 从 0 **连续递增**，引擎按此二分查找，断号=数据错乱 |
| year | 物化年份 | 历史集为真实年份（可为负）；资料集无年份语义，统一填 0 |
| regionIdx | 分类下标 | 指向 meta.txt 的 `regionList` 数组下标 |
| 标题 | 列表页显示 | 值里禁止出现半角 `\|`（工具自动物化为全角 `｜`） |

### 2.2 `detail_N.txt` —— 详情内容（每 `detailChunkSize` 条一片）

```
localId|关键词|字段值1|字段值2|...
0|切 HAL_PROT_INFO,静态变量,内存|原因背景文字|影响做法文字
```

- 第 2 列「关键词」是逗号分隔的检索词，也用于详情页关键词行展示。
- 第 3 列起按 `meta.json → fields.detail` 的顺序对应字段名。
- 字段值内的真实换行必须物化为字面 `\n` 两个字符（详情页读取时还原）。

### 2.3 `block_0.txt` —— 搜索倒排桶（文本格式）

```
桶号|id1,id2,...
0|0,5,12
17|3,7
```

- 入桶文本 = spec 的 `bucketText` 模板渲染结果（通常是 标题+关键词+分类）。
- 对入桶文本做与引擎查询侧完全一致的分词（见 §5），每个 token 哈希取模 `bucketSize` 落桶。
- 桶号**数值升序**；桶内 id 按记录顺序推送、**不去重**（两个不同 token 撞进同一桶时同 id 出现两次，与旧脚本行为一致）。

### 2.4 `meta.txt` —— 引擎物化视图（紧凑 JSON，键序即字节序）

```json
{"totalCount":1000,"regionList":["健康","急救"],"categoryList":[],
 "bucketSize":2048,
 "chunks":[{"id":0,"bucketStart":0,"bucketEnd":2047,"recordCount":1000}],
 "maps":[{"startId":0,"endId":199},...],
 "mapChunkSize":200,"detailChunkSize":100,"version":"health-ds-1"}
```

`maps[i]` 两种形态：资料集 `{startId,endId}`；历史集（v4）额外带 `{id,recordCount}`。

### 2.5 `meta.json` —— 人类自描述声明（`JSON.stringify(j, null, 2)` 缩进格式）

引擎**不读这个文件**（引擎只读 meta.txt），它给人看、给详情页读字段名：

```json
{
  "datasetId": 3, "name": "健康", "version": 1, "category": "健康", "author": "sudo",
  "totalCount": 0,
  "fields": {
    "map": ["title", "year", "category"],
    "keyword": "keywords",
    "detail": ["原因/背景", "影响/做法"],
    "filter": ["category"]
  },
  "mapChunkSize": 200, "detailChunkSize": 100, "blockCount": 1,
  "bucketSize": 2048, "yearIndex": false, "icon": "icon.png"
}
```

> spec 里写 `"totalCount": 0` 占位，工具按实际条数回填（占位写在哪一列，回填就保持在哪一列）。

### 2.6 历史集专有：`year_index.txt`

```
年份|id1,id2,...
-9000|1
-44|3,57
```

供年份搜索使用（搜「-44」→ 凯撒遇刺）。**id 重编号而此文件不重建 = 年份搜索命中错位记录**
（v1.16.35 及之前的真实事故：850 个引用 0 个匹配）。现由 existing 模式自动重建。

## 3. 三分钟上手：拆一个集

```bash
cd velaPro

# ① 拆分（产物写到 spec.outDir；--out 可临时改目标目录；--dry 只看统计）
node tools/split_dataset.js life

# ② 校验（结构 + 深度：内存重建与盘上逐字节比对）
node tools/verify_dataset.js check src/common/datasets/life life

# ③ 对比任意两份数据（逐字节）
node tools/verify_dataset.js diff 目录A 目录B

# ④ 写盘成功后必做（否则手环命中旧缓存）：
#    src/SearchEngine/SearchEngine.js  config.cache.version  +1
#    src/manifest.json                 versionName/versionCode 递增
# ⑤ 重新打包：npm run build
```

## 4. spec 字段参考（tools/specs/*.json）

一份 spec = 一个数据集的全部人类可调参数。以 `life.json` 为例：

| 字段 | 含义 |
|---|---|
| `mode` | `fresh`=从源文件拆分；`existing`=读回既有 map/detail 重建（历史集） |
| `parser.type` | `pipe5`=五列竖线行；`poems`=六列诗词行；`tsv`=制表符词条 |
| `sources` + `sourcesBase` | 源文件清单（**顺序=合并顺序**，影响采样结果）；`level` 给 tsv 每文件打标签 |
| `sample` | `{"mode":"content-length","target":N,"lengthOf":[...]}` 按字段总长降序取前 N；`{"mode":"head","target":N}` 保序取前 N；省略=全保留 |
| `dedupe` | `true`=按小写词跨文件去重（先到先得，英语集用） |
| `mapLine` | map 行模板，可用 `{localId} {year} {regionIdx}` 与任意源列名（如 `{title}·{author}`） |
| `detailKeywords` | detail 第 2 列模板（如 `{title},{author},{dynasty},{source}`） |
| `detailFields` | detail 第 3 列起的源列名数组 |
| `bucketText` | 入桶文本模板（**决定这条资料能被什么词搜到**） |
| `regionField` | 用哪一列做分类（`category` / `dynasty` / `level`） |
| `regionList` | `"sorted-set"`=解析期收集全量分类并按字符序排序；或显式数组=声明序（英语集四级=0/六级=1，**不可排序**） |
| `year` | 无年份语义的集统一物化为 0 |
| `mapChunkSize` / `detailChunkSize` | 分片大小（引擎按此定位文件，改了=全量数据迁移，勿轻易动） |
| `bucketSize` | 哈希桶总数（2048；历史集 4096） |
| `metaVersion` | meta.txt 的 version 字段 |
| `metaJson` | meta.json 声明（`fields.detail` 决定详情页字段名） |
| `yearIndex` | `true`=重建 year_index.txt（历史集） |
| `icon` | `{"char","bg","fg"}` 配合 CLI `--icon` 生成圆底字图标 |

## 5. 分词与哈希规则（为什么有的资料搜不到）

引擎查询与建桶必须用**同一套**规则，任何一边改动都会让交集变空：

```
入桶文本 → 按 [空白 , ，、] 切词：
  纯字母词 ≥3 字母 → 入桶全部前缀（"access" → ac/acc/acce/access 前 3..len 共 4 个）并小写
  纯字母词 <3      → 整词入桶小写
  其余（中文/数字/混合）→ 逐个非空字符入桶
每条记录内 token 去重；token → DJBXOR33 哈希（seed 5381，×33 异或，取无符号）→ % bucketSize
```

所以：**改标题/关键词里的任何一个字，都会改变这条资料落进哪些桶** —— 这就是为什么
任何数据变更都必须整集重建（工具自动做），而不能手工改单个 txt 文件。

## 6. 血泪教训（每一条都出过真事故）

1. **localId 必须连续**：map/detail 行首 ID 与行序绑定，跳号会让引擎二分查找读错行。
2. **采样/去重后必须重编号**：删了中间的条目，后面所有 id 都要前移，block/year_index 同步重建。
3. **year_index 是 id 的影子**：v1.16.35 曾两次重编号都没重建它 → 年份搜索全错。现由工具自动重建，`verify check` 也会盯它。
4. **改数据必须递增 `cache.version`**：引擎块缓存持久化在手环 storage 里，版本号不变就一直命中旧缓存（「清了缓存还是旧数据」的根因）。
5. **写盘前先清旧分片**：条数变少时残留的 `map_9.txt` 会带着旧 id 被引擎读到（工具已自动处理）。
6. **build success ≠ 产物正确**：webpack 会因一个逗号静默丢弃整个模块。每次构建后解包 rpk 抽查模块符号与数据文件。

## 7. 旧脚本的去向

`build_datasets_batch.js` / `build_poems_dataset.js` / `rebuild_english_cet.js` / `slim_history.js`
是 2026-09 的历史基准脚本，**已冻结**：它们的拆分语义被逐字节吸收进 `dataset_core.js`，
新工具在相同源数据上的产出与它们完全一致（map/detail/block/meta/icon 全部逐字节验证通过，2026-09-16）。
以后**只改 spec 与 dataset_core.js**，不要再往旧脚本上加逻辑。
