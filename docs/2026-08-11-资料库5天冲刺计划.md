## 二、核心主线（格式先行，顺序不可颠倒）

```
数据格式 v5（已定稿）→ 引擎适配 → 数据工具适配 → 数据生成 → 读取端适配 → 全链路验证 → 打包提交
```

**v5 格式速记**（详情见规范文档）：
```
Map：     ID | [年份] | 简约1 | 简约2 | 简约3
Detail：  ID | [年份] | 关键词串 | 详情1..N | [图片]
meta：    dataset + fields(map/detail/keyword/hiddenKeyword/image) + year(rules) + chunks/maps
```
- 字段角色：keyword / hiddenKeyword / map(≤3) / detail(N 任意) / image(仅详情)
- 存储唯一性：map 与 detail 互斥、图片仅 Detail
- 无筛选（附录 A 可扩展）

## 三、引擎适配方案（SearchEngine.js，A 主程，Day1-2）

引擎当前为 v3.4（硬编码 v4 格式），需改为**数据结构零假设、依赖 meta 配置**。逐函数改造：

### 3.1 `_loadMeta()`（核心）
- **现状**：读 v4 meta（totalCount/regionList/categoryList/chunks/maps/bucketSize）
- **改为**：读 v5 meta：
  ```js
  this.dataset   = meta.dataset || {}                  // 数据集信息
  this.fieldMap   = meta.fields.map || []              // 简约字段配置
  this.fieldDetail= meta.fields.detail || []           // 详情字段配置
  this.fieldKw    = meta.fields.keyword || []          // 关键词字段
  this.fieldHidden= meta.fields.hiddenKeyword || []
  this.fieldImage = meta.fields.image || []            // 图片字段
  this.yearCfg    = meta.year || { enable:false }      // 年份配置
  this.mapCols    = 1 + (yearCfg.enable?1:0) + fieldMap.length   // Map 列数
  this.hasImage   = fieldImage.length > 0
  ```
- 兼容：若 meta 无 `formatVersion`（旧 v4），走旧解析路径（保留旧逻辑，便于回退）

### 3.2 `_loadMapFromFile(mapId)`（动态列）
- **现状**：硬编码 4 列 → `ids/years/regionIds/titles`
- **改为**：
  ```js
  var cols = this.mapCols   // ID + [年份] + 简约N
  ids.push(parseInt(parts[0],10))
  if (yearCfg.enable) years.push(parseInt(parts[1],10))
  displayVals.push(parts.slice(1+(yearCfg.enable?1:0), cols))   // 简约列数组
  ```
- 存储：`mapData = { ids, years?, displayVals: [ [v1,v2], ... ] }`
- 说明：`displayVals` 每项是该记录简约字段值数组（长度=fieldMap.length）

### 3.3 Detail 解析（`getDoc` / `getDocSync`）（按 N 切片）
- **现状**：固定列取 年份/地区/分类/标题/关键词/原因/影响
- **改为**（统一解析函数 `_parseDetailLine(parts)`）：
  ```js
  var idx = 0
  var doc = { id: parseInt(parts[idx++],10) }
  if (yearCfg.enable) doc.year = parseInt(parts[idx++],10)
  if (fieldKw.length > 0) doc.keywords = (parts[idx++] || '').split(',').filter(Boolean)
  doc.details = parts.slice(idx, idx + fieldDetail.length)   // N 列详情
  idx += fieldDetail.length
  if (hasImage) doc.image = parts[idx] || null               // 末尾图片路径
  return doc
  ```
- 字段名映射：`detailFields[i].name` 对应 `doc.details[i]`（详情页标签）

### 3.4 `search` 展示（卡片数据）
- **现状**：regionMap 映射地区名 + title
- **改为**：卡片直接用 `mapData.displayVals`：
  ```js
  var dv = mapData.displayVals[id] || []
  return { id, year, title: dv[0] || '', subtitle: dv[1] || '', yearDisplay: fmtYear(year) }
  ```

### 3.5 年份显示 `_formatYearDisplay`
- **现状**：固定规则
- **改为**：按 `yearCfg.rules` 匹配（`min≤value≤max → display.replace('{value}',value)`），未命中用 `defaultDisplay`

### 3.6 初始化路径（splash 侧不变）
- `engine.init(basePath, cb)` / `initLight(basePath)` 签名不变，仅内部解析升级

**验收（Day2 末）**：用词典库 2 行示例（规范 6.1）手工构造 v5 数据，`getDoc(0)` 返回 `{keywords:['苹果','apple'], details:['一种蔷薇科水果',...]}`，`search('苹果')` 命中 ID0 且卡片显示"苹果 名词"。

## 四、数据工具（New PL）适配要求（A 主程 + B 协助，Day2-3）

1. **meta 输出对齐 v5**：去掉 `filter`，输出 `dataset/fields(map/detail/keyword/hiddenKeyword/image)/year/chunks/maps`（`formatVersion:5`）
2. **Map 固定列**：`ID|[年份]|简约1..3`（无图片列）
3. **Detail 固定段**：`ID|[年份]|关键词串|详情1..N|[图片]`，空值保留占位
4. **UI 简化**：字段列 → 勾选角色（关键词/隐形/简约/详情/图片）+ 填列名 + 填权重（模板式，替代原复杂独立判断）
5. 输出文件清单：meta.json + map_*/detail_* + block_* + year_index(可选) + images/

**B 的任务**：按各库模板整理原始数据（`|` 分隔），≥2000 条/库：
- 历史库：标题|年份|关键词|原因|影响（列1 转 year）
- 词典库：词|词性|别名|释义|例句|用法
- 单位库：单位|类型|全称|换算关系|说明
- 百科库：词条|领域|别名|定义|详述
