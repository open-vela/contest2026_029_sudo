## 一、项目背景与目标

### 1.1 背景

队伍拥有自研的「万象史搜索引擎 v3.4」（纯 JS 实现，专为 Vela 手表/手环设计的离线轻量级全文检索引擎），已在 openvela 官方手表模拟器上完成验证（初赛标准路径，本队未领取开发板）。本次参赛将其迁移至 openvela 快应用环境，并融合官方系统能力（健康数据、端侧 AI Agent），打造一款贴合手表真实场景的腕上搜索应用。

### 1.2 核心指标（真实承诺，杜绝夸大）

| 指标 | 数值 | 说明 |
|---|---|---|
| 检索延迟 | 0.5~1 秒（上限约 2 秒） | 模拟器实测数据 |
| 索引容量 | 40~50 万关键字（理论 100 万） | 按单字/词切分，全文子串检索 |
| 数据覆盖 | 18 万条记录（已验证） | 历史大事记等知识库 |
| 引擎内存 | < 158KB（LRU 恒定） | 2 Block + 6 Map 缓存 |
| 启动 | 首次 10-20 秒 / 二次 1-2 秒 | 索引构建与缓存恢复 |

### 1.3 目标

1. 完成一款可演示、可提交的 openvela 快应用作品（图形 + AI + 健康数据三能力落地）。
2. 充分发挥自研引擎的差异化技术价值（离线、极速、大数据量、隐私）。
3. 融合官方能力，满足「技术难度 / 产品创新 / 完整度 / AI 开发」评分维度。

## 二、产品定位

**《万象智搜》—— 腕上统一智能搜索**
一个搜索入口，搜遍「知识 + 健康 + 系统」三大数据域，0.5~1 秒离线给出短答案卡片。

- 核心价值主张：「抬腕即知」—— 知识查询、健康自省、功能直达，一个搜索框全搞定。
- 差异化叙事：**AI 负责听懂你，引擎负责答得准；没网时，引擎独扛。**

## 四、系统架构

```
┌───────────────────────────────────────────────────────────────┐
│                     应用层（快应用 UI）                        │
│  首页(搜索框+健康三卡) / 结果页 / 详情操作页 / 健康日志 / 设置   │
└──────────────────────────────┬────────────────────────────────┘
                               │
┌──────────────────────────────▼────────────────────────────────┐
│                    搜索路由层（纯 JS）                          │
│  输入 → 意图分类：知识查询 / 健康查询 / 功能直达 / 开放问题      │
│         │         │          │             │                   │
│         ▼         ▼          ▼             ▼                   │
│   本地引擎   健康适配器   路由映射表     velaclaw(AI)            │
│   (全文索引)  (实时+日志)  (功能直达)     (联网增强)             │
└──────────────────────────────┬────────────────────────────────┘
                               │
┌──────────────────────────────▼────────────────────────────────┐
│                  系统能力层（官方 API）                        │
│  @system.file / @system.storage / @service.health /            │
│  @system.velaclaw / @system.router / @system.prompt(待确认)     │
└────────────────────────────────────────────────────────────────┘
```

**双引擎路由策略（核心逻辑）：**

```
用户输入
  ├─ 命中功能映射表 → 功能直达
  ├─ 本地引擎检索（0.5~1s）
  │     ├─ 命中 → 精确答案卡片（标注"本地索引"）
  │     └─ 未命中/结果弱
  │           ├─ 联网可用 → velaclaw.ask(输入 + 本地候选依据) → AI 精炼答案
  │           └─ 断网 → 本地模糊匹配 + 相关词条推荐（离线兜底）
```

## 五、数据设计

### 5.1 知识库数据包（引擎数据格式）

沿用 v3.4 格式，由 `tools/splitData.html` 生成：

```
meta.txt           # JSON：totalCount、chunks、maps、bucketSize
block_*.txt|.bin   # 哈希桶 → ID 列表（索引）
map_*.txt          # ID → 展示数据（标题/年份/地区/分类）
detail_*.txt       # 完整内容（原因/影响等）
year_index.txt     # 年份 → ID 列表
```

多知识库 = 多份数据包（不同 dataPath），设置页切换。

**待办**：确认各知识库数据源（历史大事记已有；词典/百科/单位需采集或整理开放数据）。

### 5.2 健康日志数据

- 订阅 `service.health` 数据（HEART_RATE/SPO2/STRESS），按 `{timeStamp, value}` 追加落盘。
- 构造「日期/时段 → 数值序列」索引，支持"昨天心率趋势""凌晨压力"等时间检索。
- 生命周期：应用运行期采集，容量上限（如最近 7 天），防存储膨胀。

## 六、AI 集成设计（velaclaw）

- **调用**：`velaclaw.ask({ query, success, fail })`，`res.reply` 为回复。
- **RAG 增强**：对本地未命中的查询，将本地引擎候选结果（标题/摘要）拼入 query 上文，让 AI 基于事实作答，降低幻觉。
- **降级**：`fail` 回调（1000 AI 不可用 / 204 超时）→ 提示"AI 暂不可用"，回退本地结果或给出本地相关词条。
- **配置**：goldfish 模拟器需在 NSH 终端启动 `ai_agent`，`set_llm https://token-plan-cn.xiaomimimo.com/v1 <model> tp-套餐KEY`（大赛 Token Plan）。
- **开关**：设置页提供 AI 开关，关闭后纯本地模式。

| 首页 `pages/index` | 搜索框（键盘/语音入口）+ 实时健康三卡（心率/血氧/压力，1Hz） | input、health 订阅 |
