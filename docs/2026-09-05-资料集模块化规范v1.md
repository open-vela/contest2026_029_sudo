# 《资料库》资料集模块化规范 v1.0

> 日期：2026-09-05 · 作者：队伍 029「sudo」
> 取代：数据格式 v5 中未落地的部分；合并 fieldMapper v3.5 的字段槽位经验
> 目标：一套规范承载任意结构的资料集（历史/诗词/英语/生活百科），支持运行时动态安装与跨集搜索

---

## 一、核心概念

| 概念 | 定义 |
|---|---|
| **资料集（Dataset）** | 一个独立文件夹，含某类资料的全部文件，自带 meta.json 自描述 |
| **注册表（Registry）** | storage 中的汇总清单（key: `dataset_registry`），记录所有已安装资料集的 meta 摘要 |
| **全局 ID** | `datasetId << 20 \| localId`——每集支持最多 1,048,576 条，ID 自带归属，免映射表 |
| **数据目录** | 手表可写区 `internal://files/datasets/<集名>/`；内置资料在 rpk 的 `/common/datasets/<集名>/`（只读，注册表标注来源） |

## 二、资料集文件夹结构

```
<datasets>/<集名>/           ← 集名 = 小写英文（如 poems / english / history）
├── meta.json                # 必读清单：字段配置 + 分块信息 + 统计
├── map_0.txt, map_1.txt…    # 简约卡片分片（每行一条，| 分隔，列序由 meta.fields.map 声明）
├── detail_0.txt, …          # 详情分片（列序由 meta.fields.detail 声明）
├── block_0.bin, …           # 关键词哈希桶（BLOK 二进制，沿用 v3.4 已验证格式）
├── year_index.txt           # 年份索引（可选，仅历史类资料集有）
└── images/                  # 详情配图（可选）
```

## 三、meta.json 规范

```json
{
  "datasetId": 2,
  "name": "诗词集",
  "version": 1,
  "category": "文化",
  "author": "sudo",
  "totalCount": 10000,
  "fields": {
    "map": ["title", "author", "dynasty"],
    "keyword": "keywords",
    "detail": ["content"],
    "filter": ["dynasty"]
  },
  "mapChunkSize": 200,
  "detailChunkSize": 100,
  "blockCount": 12,
  "bucketSize": 2048,
  "yearIndex": false
}
```

### 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `datasetId` | ✓ | 全局唯一数字（0 保留给历史主集），升级不换号 |
| `name` | ✓ | 显示名（中文可，仅用于 UI 展示） |
| `version` | ✓ | 数字递增；蓝牙更新 = 同 datasetId 高 version 覆盖 |
| `category` | ✓ | 主分类（主页分类行显示用） |
| `totalCount` | ✓ | 条数（搜索结果翻页与统计用） |
| `fields.map` | ✓ | 卡片显示字段名数组，**≤3**，与 map_N.txt 的列序一一对应 |
| `fields.keyword` | ✓ | 关键词字段名（该列内容 `,`/`，` 分隔后逐词入哈希桶） |
| `fields.detail` | ✓ | 详情字段名数组（任意个，与 detail_N.txt 列序对应） |
| `fields.filter` | — | 筛选字段（如朝代/学段），值域由数据自然收集 |
| `mapChunkSize` | ✓ | 每分片条数 |
| `blockCount` | ✓ | 哈希桶文件数 |
| `yearIndex` | — | 是否有年份索引（历史类 true） |

## 四、行格式（map / detail）

- **map_N.txt**：`localId|字段1值|字段2值|…`（列序 = meta.fields.map）
- **detail_N.txt**：`localId|字段1值|字段2值|…`（列序 = meta.fields.detail；长文本中的换行用 `\n` 字面量）
- 分隔符 `|`，值内禁用裸 `|`；UTF-8 无 BOM

## 五、运行时生命周期

```
蓝牙接收完成 / 首次启动
   ↓
遍历已知的资料集目录清单（file API 无 listDir——目录清单由手机端蓝牙下发，
内置集在 /common/datasets/ 固定枚举）
   ↓
逐集读 meta.json → 校验（datasetId/version/totalCount）
   ↓
写入/覆盖 storage 注册表（同 datasetId 取高 version）
   ↓
搜索可用（无需任何预加载——块缓存按需建立）
```

## 六、跨集搜索策略

1. 读注册表 → 得到全部资料集清单（各集 meta 常驻内存，体积极小）
2. 关键词哈希后**逐集查各自的 block 桶**（哈希未命中的集一个字节都不读）
3. 命中集加载对应块（内存 LRU + storage 缓存策略：小对象缓存，大块直读）
4. 结果合并（每条结果带全局 ID → UI 显示资料集标签），按集分组或混合排序
5. 详情页按全局 ID 路由回对应集，读该集 detail 分片

## 七、缓存策略（实测依据 2026-09-05）

| 对象 | 策略 | 依据 |
|---|---|---|
| 注册表/meta/年份索引 | storage 缓存 | 读 2ms vs 直读 12ms，快 6 倍 |
| block 大块（>100KB） | 直读文件（LRU 内存缓存） | storage 写慢（5.3ms/KB）+ 单 key ≥500KB 限额余量要留给小对象 |
| 热块 | 可选 storage 缓存 | 单 key 实测 ≥500KB 可用 |

## 八、安装/更新规则（手环实测定案）

- `/common`（rpk 包内）**只读不可删**（delete 报 code=202）→ 内置集只能随应用覆盖更新
- 蓝牙资料集 → 写入 `files/datasets/<集名>/`，更新 = 删旧文件夹写新文件夹（`file.delete` 可用）
- manifest **禁止声明 minAPILevel**（手环 9 部分批次固件安装器兼容检查崩溃——2026-09-05 实锤）

## 九、手环 9 固件 CSS 雷区（工程规范，配套记录）

1. 禁用动态内联 style 绑定（`style="height: {{x}}px"`）→ 用 @media 固化 + 状态类切换
2. 禁用小数像素（`27.5px` → `28px`）
3. 禁用 `lines` / `text-overflow` 属性声明
4. `border-radius` 不得超过宽高一半
