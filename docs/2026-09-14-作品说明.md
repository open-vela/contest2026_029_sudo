## 一、作品定位

**一句话说明**：把一座小型资料馆装进手表，让用户在**不联网、不打字**的前提下，用一两个汉字就能查到想要的知识。

**场景**：手表是"抬手即用"的设备——用户想看某个知识点时，往往只有几秒钟。传统做法（打开手机、联网检索、翻阅长文）完全不适用。本作品的做法是：**把筛选过的高质量资料预置到腕上，用自研索引让检索在本地瞬间完成**，并把交互压缩到"点一下"或"输一个字"。

| **设置** | 加载数据（构建本地索引）；蓝牙接收入口；「关于」连点四下清空全部缓存 |

## 三、技术架构

### 3.1 三层结构

```
页面层（pages/*.ux）      首页 / 详情 / 收藏 / 设置 / 加载 / 确认 / 结果
      ↓
聚合层（DatasetManager）  资料集注册表 · 多引擎实例池 · 跨集聚合搜索 · 缓存清理
      ↓
引擎层（SearchEngine）    分词 → 哈希分桶 → 候选筛选 → 分片加载 → 两级缓存
```

### 3.2 资料集的组织（可插拔）

每个资料集是**自包含目录**：

```
datasets/<集名>/
├── meta.json      字段角色声明（map / keyword / detail / filter）+ 图标 + 简介
├── meta.txt       引擎物化视图（分片数量、桶大小、分类列表）
├── map_N.txt      轻量条目数据（id|year|regionId|title），每片 200 条
├── detail_N.txt   详情数据（id|关键词|字段1|字段2…），每片 100 条
├── block_0.txt    哈希索引（桶号|id 列表）
└── icon.png       资料图标
```

- **集数 = 首页入口数**，新增资料集不需要改任何页面代码；
- 引擎实例按集池化，各集配置**深拷贝隔离**（缓存键带集 ID 后缀），互不串数据。

### 3.3 检索链路

1. **分词**：查询按分隔符切词 → 中文逐字、英文取 3~N 位前缀 → 得到一组哈希；
2. **定位**：哈希 % 桶大小 → 从索引块取候选 ID（求多个哈希的并集）；
3. **筛选**：按资料集、标签（region）过滤候选；
4. **取数**：按候选 ID 从对应分片加载条目数据；
5. **聚合**：各集结果交错排序（各集第 1 条 → 各集第 2 条 …），避免单集占满首页；再按页码切片返回。

### 3.4 缓存策略

| 对象 | 位置 | 失效条件 |
| --- | --- | --- |
| 哈希索引块 | 设备 storage | 缓存版本号变更（数据更新时递增） |
| 条目数据（Map 分片） | 设备 storage | 同上 |
| 已加载分片 | 内存（LRU，上限 12） | 超出上限时淘汰最久未用 |
| 搜索结果 | 不缓存（每次实时检索） | — |

## 四、关键工程决策与踩坑记录

这份记录既是开发日志，也是本作品的"技术含金量"所在——**每个坑都对应一次真实定位与修复**。

### 4.1 数据与引擎的分词必须逐字节一致

早期资料集的索引由独立脚本生成，脚本用"整词入桶"，而引擎查询用"字母前缀 + 逐字符入桶"。结果：**中文能搜到、含字母数字的内容（如 pH 值、维生素 C）全部搜不到**。修复方式是把同一份 `tokenize` 规则贯彻到所有生成脚本，并与引擎逐条对齐。

### 4.2 构建成功 ≠ 产物正确

一次编辑数据文件时漏了一个逗号，**构建工具仍输出 build success**，但 webpack **静默丢弃了整个模块**——产物里既没有资料集清单也没有搜索函数，运行时表现为"首页退化为硬编码分类 + 搜索完全不响应"。教训：**每次构建后必须解包产物校验关键符号**，不能只看构建结果。

### 4.3 缓存不失效会让"修复"看起来无效

索引与条目数据缓存在设备 storage，键中含缓存版本号。数据更新后若忘记递增版本号，**检索读到的仍是旧数据**——表现为"明明改了却没生效"。现在数据生成脚本与版本号联动，并提供手动清缓存入口。

### 4.4 小屏固件对动态样式敏感

手环固件在渲染**动态内联 style**（尤其是返回对象形式的样式）时会出现卡顿甚至崩溃。最终方案：**全部改为 `computed` 预拼类名 + 模板纯变量插值**，形态差异一律用 `@media` 固化。

### 4.5 滚动容器的高度陷阱

结果列表曾出现"内容多了滑不动"。根因是结果区外层同时写了 `flex: 1` 与 `flex-shrink: 0`——后者使容器**被内容撑开**，永远无法成为滚动视图。修正后结果区成为独立滚动容器，页面总高恒定。

### 4.6 潜在的无限循环

引擎的内存淘汰循环以 `length >= 上限` 为条件。若上限被设为 0，则 `length >= 0` 恒真、而 `shift()` 在空数组上不改变长度 → **死循环**。已加"上限必须大于 0"的前置断言。

### 4.7 回调丢失导致界面假死

快应用在部分打包模式下存在文件读取回调丢失的情况。一旦发生，搜索 Promise 永不返回，界面既不显示结果也不显示空态。现已加**双层超时兜底**（单集 8 秒 / 页面 10 秒）。

## 六、后续优化计划

1. **搜索性能**：继续压缩单次检索的 I/O 路径（当前已做翻页成本恒定化、渐进渲染）；
2. **圆形表盘**：按需补充圆形屏样式（当前明确面向胶囊屏与方形屏）；
3. **蓝牙推送资料集**：补齐手机端推送工具与断点续传，让用户自行扩充资料；
4. **资料质量与规模**：按内容质量择优扩充，保持检索体验。

## 附：v1.16.73 架构要点补充（2026-09-18）

- **渐进式搜索加载**：读完倒排桶后统计候选的 map 分片分布，**首轮只加载命中最多的 2 个分片先出结果**（不凑满页），点「显示更多」逐片加载——首屏更快、跨分片命中不再漏。
