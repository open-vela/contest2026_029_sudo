# 《资料库》数据格式规范 v5

> 版本：v5.0（替代旧 v4 固定结构 / New PL 未定型逻辑）
> 目标：一套文件格式 + 字段配置，承载任意结构的数据库（历史/词典/单位/百科……含可选图片）
> 适用：引擎端 SearchEngine.js 适配、数据生成工具（New PL）、读取端（detail/result/index 页）适配
> 作者：队伍 029「sudo」 · 日期：2026-08-11

---

## 一、设计原则（为什么这样设计）

1. **文件结构统一、段数由 meta 声明**——Detail 的筛选/详情字段**数量每库任意**（N 详情 + F 筛选），引擎按 meta 数组长度做位置解析，解析逻辑同一套。
2. **字段角色可配置**——每条记录的字段可扮演不同角色（搜索/显示/筛选/详情/图片）。
3. **图片可选**——有图就配，没图留空，不影响解析。
4. **兼容已有资产**——Block 哈希桶、LRU 缓存、年份索引沿用已验证逻辑。

---

## 二、字段角色体系（自定义的核心）

| 角色 | 说明 | 存储 | 参与搜索 | 数量限制 |
|---|---|---|---|---|
| `keyword` 关键词 | 搜索词；多词用 `,` 或 `，` 分隔，拆开后分别索引 | Block + Detail 关键词段 | ✅ | 任意 |
| `hiddenKeyword` 隐形关键词 | 只索引不显示（拼音/别名/英文名） | 仅 Block | ✅ | 任意 |
| `map` 简约 | 搜索卡片显示（标题/摘要等） | 仅 Map | ❌ | **≤3** |
| `detail` 详情 | 详情页内容（释义/例句/原因/影响…） | Detail 详情段 | ❌ | 任意 |
| `image` 图片 | 详情配图（存路径，图片文件随包） | **仅 Detail 存路径** | ❌ | 任意 |

> **已移除**：`filter` 筛选字段（v5.1 起）。筛选值域原本就写在 meta 且常驻内存，记录级筛选价值低，为简化和省存储直接去除。若未来需要"分类浏览"，可从 `dataset.name`/数据自带分类字段扩展（见附录 A）。

**角色可组合**：同一字段可同时是 `keyword`+`map`（如"标题"既可搜又显示）或 `keyword`+`detail`。
**互斥规则**：
- `keyword` 与 `hiddenKeyword` 互斥；
- `map` 最多 3 个；
- **`map` 与 `detail` 互斥**（存储唯一性：同一字段内容只存 Map 或 Detail 一处，避免重复存储浪费）；
- **图片仅在 Detail**（详情图），Map 不存图片。
**简化规则**：`map` 角色字段**不写 Detail**（简约只进 Map）；`detail` 角色字段**不写 Map**。

## 三、文件清单

```
<知识库目录>/（如 src/common/词典/）
├── meta.json              # 数据集信息 + 字段配置 + 分块信息（必填）
├── map_0.txt, map_1.txt…  # 简约卡片数据（按 mapChunkSize 分片）
├── detail_0.txt, …        # 详情数据（按 detailChunkSize 分片）
├── block_0.bin, …         # 哈希桶索引（二进制，可回退 .txt）
├── year_index.txt         # 年份→ID 索引（可选，year.enable=true 时）
└── images/                # 图片资源（可选，随 rpk 打包）
```

## 四、meta.json 完整定义

```json
{
  "formatVersion": 5,

  "dataset": {
    "name": "历史库",
    "version": "1.0.0",
    "author": "Soodok",
    "description": "中国与世界历史大事记",
    "icon": "/common/logo.png"
  },

  "totalCount": 2533,
  "bucketSize": 4096,

  "fields": {
    "map": [
      { "name": "标题", "weight": "high" },
      { "name": "摘要", "weight": "medium" }
    ],
    "detail": [
      { "name": "原因/背景" },
      { "name": "影响" }
    ],
    "keyword": [ { "name": "关键词" } ],
    "hiddenKeyword": [],
    "image": [ { "name": "配图" } ]
  },

  "year": {
    "enable": false,
    "rules": [ { "min": 1, "max": 500, "display": "唐代" } ],
    "defaultDisplay": "公元{value}年"
  },

  "chunks": [
    { "id": 0, "bucketStart": 0, "bucketEnd": 649, "recordCount": 4009 }
  ],
  "mapChunkSize": 100,
  "detailChunkSize": 100,
  "maps": [
    { "id": 0, "startId": 0, "endId": 99, "recordCount": 100 }
  ]
}
```

**字段说明**：
- `fields.map`：数组，第 i 项对应 map 文件第 i 个简约列；`weight` 用于排序权重（high/medium/low）
- `fields.detail`：详情段各列标签（详情页按此渲染标题）
- `fields.keyword` / `fields.hiddenKeyword`：搜索字段（引擎据此收集索引词）
- `fields.image`：图片字段（Detail 存详情图路径，指向 `images/` 下）
- `year.rules`：年份显示规则（范围→文本，`{value}` 占位）

## 五、文件格式规范

### 5.1 map_*.txt（每行一条，`|` 分隔，固定列序，纯文字无图片）

```
ID | [年份] | 简约1 | 简约2 | 简约3
```

| 列 | 说明 |
|---|---|
| ID | 记录号（0 起，与 Block/Detail 一致） |
| 年份 | `year.enable=true` 时存在；否则无此列 |
| 简约1..3 | 对应 `fields.map` 各列；不足的列留空 |

**示例**（year 开 + map 两列）：
```
12|221|秦始皇统一六国|秦王嬴政灭六国建立秦朝
```

### 5.2 detail_*.txt（每行一条，`|` 分隔，**段数由 meta 声明**）

```
ID | [年份] | 关键词串 | 详情1..N | [图片路径]
```

| 段 | 说明 |
|---|---|
| ID | 记录号 |
| 年份 | `year.enable=true` 时存在 |
| 关键词串 | 关键词字段值（`fields.keyword`），多词用 `,` 连接；`hiddenKeyword` 不入此段 |
| 详情段 | `fields.detail` 各列值，段内用 `\|` 分隔；**共 N 列**（N=meta.fields.detail.length）；N=0 则无此段 |
| 图片路径 | 可选，最后一段 |

**解析规则（引擎统一逻辑）**：
```
第0列=ID
第1列=年份（year.enable 时）
第2列=关键词串（keywordFields 存在时）
第3..3+N-1列=详情段（N = meta.fields.detail.length）
末尾可选1列=图片路径（meta.fields.image 存在时）
```
**空值必须保留占位**（`||`），禁止跳段省略——位置由 meta 数量决定，天然支持任意字段数。

**示例**（历史库：N=2 原因/影响，有图）：
```
12|221|秦始皇,统一六国|战国末期连续征战|建立中央集权帝国|images/hist/12.png
```
**示例**（词典库：N=3 释义/例句/用法，无图）：
```
88||苹果,apple|一种蔷薇科水果|He ate an apple.|常作可数名词
```

### 5.3 block_*.bin（二进制，沿用 v3.4 格式）

- 头部：`BLOK(4B)|version(4B)|chunkId(4B)|bucketCount(2B)` + 桶条目 `bucketIndex(2B)|idCount(2B)|ids(idCount×4B)`
- 索引词 = 关键词字段 + 隐形关键词字段，**每个词整词哈希 + 每字符哈希**（`hashCode`，djb2 变体），取模 `bucketSize`
- 无二进制时回退文本：`bucketIndex|id1,id2,...`

### 5.4 year_index.txt（可选）

```
年份|id1,id2,id3
```

### 5.5 images/ 目录

- 图片路径存于 Map/Detail 的图片列，值为相对 `common/` 的路径，如 `images/hist/12.png`
- 页面渲染：`<image src="/common/images/hist/12.png">`（快应用路径以 `/common/` 开头）

## 六、完整示例（两个知识库，各 2 行，验证格式设计）

### 6.1 词典库（无年份，F=1 语言，N=3 释义/例句/用法，无图）

**meta.json**（精简）：
```json
{
  "formatVersion": 5,
  "dataset": { "name": "词典库", "version": "1.0.0", "author": "Soodok" },
  "totalCount": 2,
  "fields": {
    "map":    [ { "name": "词" }, { "name": "词性" } ],
    "detail": [ { "name": "释义" }, { "name": "例句" }, { "name": "用法" } ],
    "keyword": [ { "name": "词" }, { "name": "别名" } ],
    "hiddenKeyword": [],
    "image": []
  },
  "year": { "enable": false },
  "mapChunkSize": 100,
  "detailChunkSize": 100
}
```

**map_0.txt**（ID|词|词性）：
```
0|苹果|名词
1|apple|名词
```

**detail_0.txt**（ID|关键词串|释义|例句|用法）：
```
0|苹果,apple|一种蔷薇科水果|He ate an apple.|常作可数名词
1|apple,苹果|一种水果；也指苹果公司|Apple is a tech company.|作名词或专有名词
```

**搜索**："苹果"或"apple"均命中 0、1；卡片显示"苹果 名词"；详情分段显示 释义/例句/用法。

### 6.2 历史库（有年份，N=2 原因/影响，有图）

**meta.json**（精简）：
```json
{
  "formatVersion": 5,
  "dataset": { "name": "历史库", "version": "1.0.0", "author": "Soodok" },
  "totalCount": 2,
  "fields": {
    "map":    [ { "name": "标题" }, { "name": "摘要" } ],
    "detail": [ { "name": "原因/背景" }, { "name": "影响" } ],
    "keyword": [ { "name": "标题" }, { "name": "关键词" } ],
    "hiddenKeyword": [],
    "image": [ { "name": "配图" } ]
  },
  "year": { "enable": true, "rules": [ { "min": 1, "max": 500, "display": "唐代" } ], "defaultDisplay": "公元{value}年" },
  "mapChunkSize": 100,
  "detailChunkSize": 100
}
```

**map_0.txt**（ID|年份|标题|摘要，纯文字）：
```
12|221|秦始皇统一六国|秦王嬴政灭六国建立秦朝
13|2026|资料库项目启动|参赛作品开发进行中
```

**detail_0.txt**（ID|年份|关键词串|原因|影响|图片）：
```
12|221|秦始皇,统一六国|战国末期连续征战|建立中央集权帝国|images/hist/12.png
13|2026|资料库,项目|参加openvela大赛|开发进行中|
```

**搜索**："秦"（单字）命中 ID12；年份 221 显示为"公元221年"（未命中规则则走 defaultDisplay）；详情页渲染 原因/影响 + 图片。

> 两例对比可见：**同一套引擎逻辑，仅 meta 不同，即承载完全不同的数据结构**——这就是"高自定义化数据库"底座。

## 七、引擎适配清单（SearchEngine.js）

| 位置 | 现状（v3.4） | 改为（v5） |
|---|---|---|
| `_loadMeta` | 读 v4 meta（regionList/categoryList） | 读 v5 `fields`（map/detail/keyword/hiddenKeyword/image）+ `dataset` + `formatVersion`；保留旧 v4 兼容或直接切换 v5 |
| `_loadMapFromFile` | 硬编码 4 列 ID/年份/地区/标题 | **列数由 meta 动态定**：`ID|[年份]|简约1..N`；存通用 `displayVals` 数组 |
| Detail 解析（getDoc） | 固定列取原因/影响 | **按 meta 的 N 数量解析**：读 `fields.detail.length` → 从关键词串后按位置切片详情段 → 返回 `{keywords, details[], image}`；字段名取 meta 配置 |
| `search` 展示 | 用 regionMap 映射地区名 | 卡片数据直接来自 Map 简约列（`mapFields` 名作标签可选） |
| 年份显示 | `_formatYearDisplay` 固定规则 | 按 `meta.year.rules` 动态映射（含 `defaultDisplay`） |

**目标**：引擎对"数据结构"零假设，只依赖 `meta.fields` 配置。

## 八、读取端适配清单

| 文件 | 现状 | 改为 |
|---|---|---|
| `detail.ux` | 硬编码"关键词/原因/影响"区块 | 按 `meta.fields.detail` 动态渲染（name=标签，value=内容）；图片列渲染 `<image>` |
| `result.ux` | 硬编码年份/地区/标题 | 简约列动态显示（取前 2 列作标题/摘要） |
| `index.ux` | 硬编码 categories/regions 数组 | 移除筛选标签（v5 无筛选）；保留搜索框/键盘/结果预览 |
| `settings.ux` | 固定 | 知识库切换列表从可用库 meta.dataset.name 生成 |

## 九、数据生成工具（New PL）输出对齐要求

New PL v2.5 生成的 meta/map/detail/block 必须与本文第五、六节一致：
1. **meta 输出 v5 结构**（含 dataset、fields、year、chunks/maps）
2. **Map 固定列**：`ID|[年份]|简约1..3|[图]`（不要动态省略）
3. **Detail 固定段序**：`ID|[年份]|关键词串|筛选段|详情段|[图]`，**空值保留占位**
4. **图片列**：Map/Detail 可选最后一列，值 = `images/<库名>/<file>`
5. 移除/简化"每字段独立判断"UI：改为**每列勾选角色 + 输入列名**（模板式配置，更易懂）

## 附录 A：可选筛选扩展（当前 v5 已去除，如需可加回）

若未来需要"分类浏览/筛选"，最小改动方案：
1. meta.fields 增加 `filter`：`[ { "name":"分类", "values":["古代","现代"] } ]`
2. Detail 行在关键词串后插入筛选列（位置在详情段之前）：
   `ID|[年份]|关键词串|筛选1..F|详情1..N|[图片]`
3. 引擎解析：读 `fields.filter.length`（F），关键词串后先切 F 列筛选再切 N 列详情
4. 读取端：从 meta 生成筛选标签，按筛选值过滤结果

> 因筛选值域已在 meta（常驻内存），标签生成零成本；记录级过滤仅在启用该功能时才需解析 Detail 筛选列。
